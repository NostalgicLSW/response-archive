# 적대적 리뷰와 재평가

검토일: 2026-11-14. 공개 전의 실패 조건과 배포 파일을 재평가한다.

## 판정

**수정본의 소스 공개와 macOS Codex CLI 중심의 공개 시험판은 가능하다. 정식 안정판 또는 Work·모든 환경의 완전한 지원으로 발표할 근거는 부족하다.**

이전 배포 파일 점검보다 강한 조건을 적용하자 공개 전에 수정해야 할 문제가 재현됐다. 이전 ZIP을 그대로 공개하는 판단은 유지하지 않는다. 아래 수정이 반영된 새 ZIP과 함께 공개해야 한다. GitHub에는 아직 업로드하지 않았으며 원격 CI 실행 결과도 없다.

## 확인된 문제와 수정

모든 공격·오류 주입은 임시 폴더와 가짜 비밀값으로 수행했다. 실제 사용자 파일을 삭제하거나 실제 토큰을 넣어 시험하지 않았다.

| 우선순위 | 재현한 문제 | 수정 및 재평가 |
| --- | --- | --- |
| P1 | 손상된 설치 정보에 `child/../../outside.txt`를 넣으면 작업 폴더 밖의 시험 파일을 삭제할 수 있었음 | 상위 경로·절대경로·심볼릭 링크 차단, 관리 파일 경로·경계·설치 파일 목록 검증. 작업 폴더 밖의 파일 보존 확인 |
| P1 | 파일 복사 도중 실패하면 실행 불가능한 스킬이 노출되고 재설치가 막혔음 | 비공개 임시 폴더에서 복사한 뒤 완성된 설치만 공개 |
| P1 | 파일 변경 직후 오류나 강제 종료가 발생하면 설치·제거·Git 설정이 서로 맞지 않았음 | 변경 전 복구 정보 보관, 중단 후 다음 명령에서 복구. 설치·제거·Git 변경의 실제 프로세스 종료와 재시도 확인 |

| P1 | 공개 폴더 전체를 재귀적으로 ZIP에 넣어 추가된 개인 파일이 포함될 수 있었음 | `release-files.txt`의 정확한 파일만 포함. Git 추적 대상도 목록 밖이면 차단 |
| P1 | 작업 파일에서는 지웠지만 Git 인덱스에 남은 비밀값을 놓쳤음 | 실제 커밋에 들어갈 Git 인덱스의 내용도 검사. 작업 파일과 인덱스가 다르면 중단 |
| P1 | 비밀값 점검 후 파일이 바뀌면 검사하지 않은 내용이 ZIP에 들어갈 수 있었음 | 최종 검사한 바이트 스냅샷만 ZIP에 기록. 검증 실패 시 이전 ZIP 보존 |
| P2 | 손상된 저장 정보에서 오류 화면이 나오거나 점검 기능이 정상으로 판정했음 | 형식 검증, 구조화된 실패 반환, 저장 위치·기록 해시 점검 추가 |
| P2 | 작업 폴더 이름의 `#`, `>`, `?` 때문에 파일 링크가 깨졌음 | 링크 대상을 URI 형식으로 인코딩하고 실제 경로로 되돌릴 수 있는지 확인 |

| 문서 | 시험판과 Work의 실제 검증 범위가 첫 화면에서 분명하지 않았음 | README 상단에 공개 시험판, CLI 우선 검증, Work 실험 지원을 표시 |

P1은 이번 공개 전에 해결해야 할 데이터 보존·범위·노출 문제로 분류했다. P2는 실패 처리·읽기 경험·배포 신뢰성 문제다. 로컬 관리 정보가 손상됐다는 조건과, 임의의 원격 공격자가 실행 권한 없이 공격할 수 있다는 주장은 구분한다.

## Recursive eval-driven loop

평가를 통과시키기 위해 검사 강도를 낮추지 않았다. 재현 사례를 남기고 수정한 뒤, 새 실패 조건을 추가했다. 제거 후 Git 규칙 유지처럼 의도적으로 바꾼 사용자 동작은 문서와 기존 평가 계약에도 명시했다.

| 순서 | 평가 결과 | 후속 조치 |
| --- | --- | --- |
| 기존 기준 | 기본 28개 통과 | 기존 근거 보존 |
| 적대적 1차 | 43개 중 새 15개 실패 | 경로·복구·개인 기록·배포 차단 수정 |
| 1차 재평가 | 43/43 통과 | 새 복구 장치에 강제 종료·외부 편집 추가 |
| 복구 후속 | 49개 중 점검 기능 1개 실패 | 손상된 저장 정보도 점검하도록 수정 |
| 복구 재평가 | 49/49 통과 | Git 인덱스와 검사 후 변경 사례 추가 |
| 공개 후속 | 51개 중 2개 실패 | 인덱스 내용과 ZIP 바이트 스냅샷 검사 추가 |
| 공개 재평가 | 51/51 통과 | 토큰 모양이 없는 개인 메모 사례 추가 |
| 목록 후속 | 52개 중 1개 실패 | 공개 목록 밖의 Git 추적 파일도 차단 |
| 목록 재평가 | 52/52 통과 | 루트 제외 규칙 이전의 중단 사례 추가 |
| 비공개 복구 후속 | 53개 중 1개 실패 | 내부 관리 폴더의 독립 제외 규칙 추가 |
| 최종 회귀 평가 | **53/53 통과** | 코드 고정 후 실제 CLI·원문·배포 파일 재검증 |

동시 저장 200건, 저장 전·공개 후 종료, 설치·제거 도중 종료, 외부 편집 보존, 재시도, 인코딩과 Git 노출 사례를 포함한다. 중단 이후 사용자가 같은 파일을 따로 바꾸면 자동 덮어쓰기 대신 `recovery_conflict`로 멈추는 것이 통과 기준이다.

## GitHub 공개 절차

1. 공개할 파일을 `release-files.txt`와 비교한다. 실행 로그와 이전 시험 ZIP은 올리지 않는다.
2. 커밋할 파일을 준비한 뒤 Git 저장소에서 `python3 -B tools/check_release.py --tracked`를 실행한다. 알려진 비밀 패턴, 개인 경로, 실행 기록, 목록 밖 파일과 인덱스 차이가 있으면 중단한다.
3. 소스를 공개 시험판으로 업로드한다. **업로드 뒤의 CI는 이미 공개된 비밀을 되돌릴 수 없으므로 로컬 사전 검사를 생략하지 않는다.** 이 검사는 과거 Git 커밋 이력 전체를 검사하지 않는다.
4. GitHub Actions가 성공하는지 확인한다. 외부 Action은 공식 저장소에서 확인한 전체 커밋 SHA로 고정하고, 권한은 `contents: read`, checkout은 `persist-credentials: false`다.
5. `python3 -B tools/package.py`와 `python3 -B evals/release_eval.py`로 만든 ZIP과 SHA-256 파일을 Pre-release에 첨부한다.

Action 고정은 [GitHub의 외부 Action 보안 권고](https://docs.github.com/en/actions/reference/security/secure-use)에 따른다. 확인한 공식 커밋은 [checkout](https://github.com/actions/checkout/commit/11d5960a326750d5838078e36cf38b85af677262), [setup-python](https://github.com/actions/setup-python/commit/a26af69be951a213d495a4c3e4e4022e16d87065)이다. 원격 CI가 실제로 실행됐다는 뜻은 아니다.

## 남은 범위와 중단 기준

- 스킬 지침과 저장 도구 호출에 기반한다. 에이전트의 모든 답변을 강제로 가로채거나 누락을 불가능하게 하는 기능은 아니다.
- Work의 새로운 모드 시작과 UI 버튼 직접 조작, 최종 파일 링크의 앱 클릭 검증은 이번 리뷰에서 수행하지 않았다. 기존 연결 근거와 URI 문자열 검사를 UI 완료로 확대하지 않는다.
- Windows·클라우드 Work·네트워크 파일시스템·전원 손실 전체·장기 대량 기록 성능은 검증되지 않았다.
- 공통 저장 도구를 우회하는 다른 작성자나 같은 사용자 권한의 공격적 파일시스템 교체 전체를 통제하지 않는다. 외부 편집을 발견하면 보존하고 중단한다.
- 비밀 패턴 검사는 모든 비밀 형태를 인식하는 보안 인증이 아니다. 정확한 공개 파일 목록과 수동 내용 검토를 함께 사용한다.
- 이번에 재현한 공개 차단 문제는 수정됐다. 실제 GitHub 저장소와 원격 CI가 아직 없으므로 그 단계의 성공을 미리 선언하지 않는다.

따라서 **소스 공개: GO / 범위를 밝힌 공개 시험판: GO / 전 환경 안정판: NO-GO**로 판단한다.
