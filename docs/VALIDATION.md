# 검증 기록

기능 검증일: 2026-11-14. 공개 문서·배포 경로 재점검: 2026-11-15 (Asia/Seoul). 최초 기능 검증은 0.1.0 기준이며, 0.1.1은 문서·프로젝트 내부 임시 경로와 배포 버전을 정리한다. 저장·설정 처리 로직은 바꾸지 않는다.

## 평가 → 수정 → 재평가

정상 예시만 실행하지 않고 실패 조건을 추가해 문제를 재현했다. 원래 실패 기록을 남긴 뒤 코드를 수정하고 같은 사례와 기존 동작을 함께 다시 평가했다.

| 평가 루프 | 발견한 문제 | 수정 후 결과 |
| --- | --- | --- |
| 설치 중 다른 곳에서 설정 생성 | 새로 생긴 설정을 덮어쓸 수 있었음 | 기존 내용이 있으면 중단하고 보존 |
| Git 옵션 변경 중 쓰기 실패 | 일부 설정만 변경된 상태가 남았음 | 제품이 쓴 부분만 이전 값으로 복구 |
| 손상된 설정 읽기 | 오류 결과 대신 실행 오류 화면 발생 | 구조화된 실패 이유 반환 |
| 설치한 폴더 이동 | 잘못된 위치 저장은 막았지만 제거도 막혔음 | 소유한 파일을 확인한 뒤 제거·재설치 허용. 기록 보존 |

기본 28개에 공개·중단·관리 정보 손상에 대한 적대적 사례를 추가해, 최종 로컬 회귀 평가는 **53개 모두 통과**했다. 발견·수정 과정과 범위는 [적대적 리뷰](ADVERSARIAL_REVIEW.md)에 기록했다. 전체 로그와 소스 해시는 로컬 `evals/runs/`에 보존하며 배포 ZIP에는 넣지 않는다.

## 공통 저장·설정 도구

- 20개 독립 프로세스에서 각각 10건, 총 200건 저장: 순번 중복·덮어쓰기·본문 손실 없음.
- 한글·CRLF·마지막 줄바꿈 없는 본문·Markdown 표와 코드 문자를 바이트 그대로 보존.
- 같은 답변 식별자로 재시도하면 같은 파일 반환. 다른 내용을 같은 식별자로 보내면 중단.
- 저장 직전과 파일 공개 직후 프로세스 종료를 재현. 불완전한 답변을 최종 파일로 공개하지 않고, 재시도 시 기존 완성 파일을 확인.
- 저장에 실패하거나 잠금을 기다리다 시간이 초과하면 성공 경로를 반환하지 않음.
- 외부에서 수정하거나 삭제한 과거 기록을 자동 복원·덮어쓰기하지 않음.
- 심볼릭 링크로 연결된 관리 경로를 따라 다른 작업 폴더에 쓰지 않음.
- 기존 지침, 우선 적용되는 `AGENTS.override.md`, 기존 Git 규칙과 설치 후 추가한 사용자 내용을 보존.
- 설치된 파일이나 제품 관리 구역을 사용자가 바꾸면 자동 제거를 중단.
- 이동한 폴더에서는 저장을 중단하되, 기록을 보존하면서 제거·재설치 가능.
- 설치·제거·Git 변경 중 오류와 강제 종료 시 다음 명령에서 복구. 복구 대상이 외부에서 바뀌었으면 덮어쓰지 않고 중단.
- 제거 후에도 선택한 Git 포함·제외 정책을 보존. 내부 복구 정보는 첫 설치 도중 중단되더라도 Git에서 제외.
- CLI와 GUI 출력은 같은 폴더에서도 호출별로 선택. 폴더 설정에 출력 모드를 고정하지 않음.

## 실제 대화형 Codex CLI

`codex exec`가 아닌 실제 대화형 TUI를 별도 터미널에서 실행했다. 제품을 임시 작업 폴더의 `.agents/skills`에 설치하고, 독립된 설정 폴더를 사용했다.

**19개 행동 확인 항목 통과:** 일반 질문 자동 기록, 원문에 표·코드 블록이 있는 답변, 대화 도중 native 설정으로 끄기·다시 켜기, 실제 `/compact` 후 기록 유지, 폴더 기록 끄기, 새 세션 꺼짐 유지, 다시 켠 뒤 저장, 권한 부족 실패 복귀, native 스킬이 꺼진 새 세션의 일반 답변.

추가 검사기는 실행 코드를 평가하거나 재실행하지 않고 도구 호출에 담긴 원문을 해석했다. **저장된 5개 본문이 작성된 원문과 정확히 일치**했고, 저장에 실패한 본문도 최종 답변의 앞부분에 **원문 전체가 그대로 남은 것**을 확인했다.

표본은 macOS, Python 3.9.6, Codex CLI 0.163.0 환경이다. 다른 모델·버전의 모든 응답을 보장하는 결과는 아니다.

## 배포 ZIP

소스 폴더에서의 실행과 별도로 ZIP을 한글·공백이 있는 임시 경로에 풀어 확인한다. 외부 패키지 설치 없이 설치·원문 저장·동일 답변 재시도·CLI/GUI 표시·점검·켜기/끄기·Git 옵션·설치 도구 자체 제거와 기록 보존을 시험한다. 인증 파일·실제 응답·실행 로그가 ZIP에 들어가지 않는지도 확인한다. `evals/release_eval.py`로 재현할 수 있다.

공개 목록의 정확한 파일과 실제 ZIP 바이트를 검사한다. Git 검사에서는 작업 파일뿐 아니라 인덱스에 남은 비밀값과 공개 목록 밖 파일도 차단한다. 알려진 비밀 패턴 검사를 모든 비밀의 탐지 보장으로 표현하지 않는다.

## Codex GUI와 로컬 Work 연결

실제 설치한 제품으로 앱의 모델·도구 실행 기록과 파일을 함께 확인했다.

- 새 Codex 앱 채팅의 일반 질문이 저장되고 GUI용 파일 링크를 반환.
- 열린 대화에서 임시 프로젝트의 native 비활성화 설정을 반영해 일반 답변으로 복귀.
- 폴더 기록을 끈 뒤 새 Codex 앱 채팅에서도 일반 답변 유지.
- 앞서 사용자가 Work로 확인한 기존 로컬 시험 채팅에서도 저장·native 비활성화 반영·폴더 기록 끄기·일반 답변 복귀.
- 새로 저장한 GUI·Work 답변 2개는 작성된 원문과 바이트 단위 일치. 이전 기록은 그대로 보존.

이 native 비활성화 시험은 **임시 프로젝트 설정 파일을 통해** 수행했다. 앱의 스킬 끄기 버튼을 직접 클릭한 시험과는 구분한다. Work는 기존 채팅을 재사용했으며 현재 UI 모드와 새 Work 채팅 시작을 독립적으로 확인하지 않았다. 이 버전에서 문서 링크 클릭·미리보기를 다시 조작하지는 않았고, 앞선 분리 시험에서 사용자 확인과 스크린샷으로 확인한 호스트 기능을 활용한다.

## 환경 보존 관찰

설치·제거 도구는 지정한 작업 폴더만 변경한다. native 설정은 읽기만 하며 전역 설정에 쓰는 코드는 없다. 평가용 인증 사본은 종료 시 삭제했다. 저장되는 답변은 평문이며, 원문 보존은 비밀값 자동 제거를 뜻하지 않는다.

첫 CLI 평가와 앱 평가를 병렬 실행한 관찰 구간에서 사용자 파일의 비교값 변화가 관찰됐다. 원인이나 변경 주체를 단정하지 않고 원본을 복구하거나 덮어쓰지 않았다.

이를 분리하기 위해 **최종 제품의 CLI 평가를 앱 조작 없이 독립적으로 다시 실행**했다. 같은 19개 행동 확인이 다시 통과했고, 사용자 `config.toml`과 `auth.json`의 **내용 해시와 수정 시간이 모두 유지**됐다. 임시 인증 사본도 삭제됐다. 기능 평가 성공과 외부 환경의 변화 여부를 별도 항목으로 기록한다.

## 아직 보장하지 않는 사항

- 에이전트가 저장 도구 호출을 생략하는 경우까지 막는 플랫폼 차원의 강제 기록.
- 많은 스킬 때문에 카탈로그가 생략되는 환경, 모든 프로젝트 지침 조합.
- UI 버튼 자체, 모든 별도 프로필·명령줄 설정·관리형 클라우드 정책의 재구성.
- 새 Work 모드의 완전한 설치 흐름, 클라우드 Work, Linux·네트워크 파일시스템. Windows는 미검증 후보가 아니라 현재 파일 잠금 구현으로 지원하지 않는 환경이다.
- 전원 손실이나 파일시스템 고장 전체에 대한 복구. 프로세스 종료 시험과 구분.
- 저장 기능을 켜고 끌 때 답변의 품질이 항상 동일하다는 보장.

## GitHub 공개 이후 재점검

소스 저장소와 v0.1.0 공개 시험판이 실제로 게시됐다. [공개 README 갱신의 CI](https://github.com/NostalgicLSW/response-archive/actions/runs/43700196560)에서 공개 목록 검사, 회귀 평가, ZIP 생성과 ZIP 설치 평가가 성공했다. 로컬 준비 상태와 원격 실행 완료를 구분한다.

2026-11-15 재점검 시작 시 공개 `main`의 29개 파일을 로컬 검토본의 Git blob 값과 대조했고 모두 일치했다. 최초 v0.1.0 태그와 당시 `main`은 README와 평가용 임시 경로 등 7개 파일이 달랐다. 기존 태그는 보존하고 0.1.1에 수정본을 반영한다. 릴리스의 Source code ZIP은 그 태그 시점의 소스이며, 별도로 만든 배포 ZIP과 같은 파일이라고 주장하지 않는다.

이번 반복 평가에서 수정 전·후 회귀 사례 53개가 모두 통과했고, 수정본 ZIP의 설치·원문 저장·재시도·CLI/GUI 표시·제거 등 11개 배포 항목도 통과했다. 별도 점검에서는 문서의 여섯 가지 누락·모순을 수정하고 0.1.0 → 0.1.1 갱신, 기존 지침·본문·Git 선택·재시도 식별자 보존을 확인했다. 재설치는 기록을 켠 상태로 시작하므로 이전 꺼짐 상태를 유지하려면 다시 꺼야 한다.

실제 모델·GUI·Work와 컨텍스트 복원 품질은 이번에 새로 평가하지 않았다. 이전의 실제 모델 검증 결과를 새 실험으로 계산하지 않는다. 저장 도구의 실행 로직은 버전 표기 외에 변경하지 않았다.
