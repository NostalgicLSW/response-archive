# 제품 정의 — Response Archive 0.1

## 목적

에이전트의 긴 최종 답변을 Markdown 문서로 읽고, 작업 폴더에 날짜와 순서에 따라 보관한다. 예를 들어 오류의 원인, 수정 내용, 테스트 결과와 남은 작업을 나중에 다시 확인하고 다른 AI와 후속 작업을 검토할 때 참고할 수 있다.

기록은 맥락을 다시 파악할 근거다. 모델의 컨텍스트 용량을 늘리거나 과거 기록을 자동 검색·삽입하는 기능은 없으며, 토큰 절감이나 작업 재개 정확도 향상은 검증하지 않았다.

## 확정 요구사항

| 항목 | 동작 |
| --- | --- |
| 적용 위치 | 현재 세션의 정확한 작업 폴더 |
| 저장 대상 | 완성된 최종 답변 전체. 진행 안내·도구 출력·승인 요청 제외 |
| 저장 형식 | `responses/YYYY-MM-DD/NNN_설명.md` |
| 날짜 | 저장 시점의 사용자 현지 날짜 |
| 순번 | 날짜별로 증가. 여러 세션이 동시에 저장하거나 제목이 달라도 중복 금지 |
| 원문 | 줄이거나 다시 쓰지 않고 그대로 보관 |
| 이전 기록 | 덮어쓰기·자동 수정·자동 삭제 금지 |
| CLI | 최종 출력에 경로만 표시 |
| GUI·Work | 저장 위치와 파일 링크 제공. 문서 열기·미리보기는 호스트 앱 기능 활용 |
| 지속 | 같은 폴더의 다음 세션에도 활성화 상태 유지 |
| 비활성화 | 일반 답변으로 돌아가고 상태 유지. 과거 기록은 보존 |
| 실패 | 원래 답변 전체와 실제 저장 실패 이유 표시 |
| Git | 기본 제외. 포함 여부 선택 가능 |

## 첫 버전 구성

스킬은 답변 작성과 사용 흐름을 안내한다. 공통 저장 도구는 원문 저장·순번·기존 기록 보호·실패 반환을 담당한다. 폴더 설정과 짧은 프로젝트 지침은 다음 세션에 같은 사용 절차를 연결한다.

첫 버전은 로컬 설치형이며 별도 서버·저장용 API 키·전역 설정 변경을 요구하지 않는다. macOS를 우선 검증하며 Windows는 현재 지원하지 않는다. 자동 기록은 에이전트의 지침 준수에 기반하며 플랫폼 차원의 전량 수집을 보장하지 않는다.

응답은 암호화하지 않은 파일로 저장하며 비밀값을 자동 제거하지 않는다. Git 제외는 접근 통제나 동기화 방지 기능이 아니다. 저장 도구 자체는 네트워크 요청이나 자동 업로드를 하지 않는다.

제거해도 과거 기록과 선택한 Git 포함·제외 정책은 유지한다. 설치·제거·설정 변경의 중단을 복구하며, 관리 정보가 손상되거나 외부 변경과 충돌하면 사용자 파일을 덮어쓰지 않고 중단한다. 공개 배포는 시험판으로 분류하고 실제 검증 범위를 명시한다.

## 사용 흐름

1. 작업 폴더에 설치하고 사용자 시간대를 정한다.
2. 같은 폴더에서 질문하거나 작업을 요청한다.
3. 답변이 완성되면 새 문서로 저장하고 위치를 표시한다.
4. 다음 세션에서도 같은 설정을 사용한다.
5. 원하면 기록을 끈다. 다시 켜기 전까지 일반 답변을 표시한다.
6. 저장하지 못하면 답변과 실패 이유를 직접 표시한다.

## 후속 검증·확장

많은 스킬이 설치된 환경, 클라우드 Work, 다른 운영체제, 네트워크 폴더, 앱의 스킬 끄기 버튼 자체, 과거 기록 자동 검색은 별도 검증 대상으로 둔다. 확인된 구현 결과는 `VALIDATION.md`에서 관리한다.
