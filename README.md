# Response Archive

**Codex로 작업할 때 AI의 긴 답변을 Markdown 문서로 읽고, 프로젝트 폴더에 날짜별로 보관하는 도구입니다.** 기존 Codex에 추가해서 사용합니다.

## 왜 만들었나요?

Codex CLI에서 개발 작업을 하면 AI가 작성한 설명, 표, 코드 예시가 터미널에 계속 쌓입니다. 긴 답변을 읽으려면 화면을 오르내려야 하고, 나중에 다시 보려면 이전 대화를 찾거나 내용을 따로 복사해야 합니다.

Response Archive는 답변이 완성될 때 본문 전체를 `.md` 파일로 저장하고, 대화에는 저장 위치를 표시합니다. 터미널에는 짧은 경로가 남고, 긴 설명은 파일을 열어 읽을 수 있습니다.

## 사용하면 무엇이 달라지나요?

예를 들어 Codex에게 다음과 같이 요청합니다.

> 로그인 오류의 원인, 수정한 내용, 테스트 결과를 정리해줘.

기록이 켜져 있으면 긴 답변 대신 다음과 같은 경로가 표시됩니다.

```text
responses/2026-11-15/001_login-error-fix.md
```

파일을 열면 AI가 작성한 답변 전체를 읽을 수 있습니다. 제목, 표, 코드 블록은 Markdown 원문으로 남습니다. CLI에서는 경로를 안내하고, Codex GUI·로컬 Work에서는 앱이 제공하는 파일 링크와 미리보기를 활용합니다.

- **지금 읽기:** 터미널에서 긴 답변을 찾아 스크롤하는 대신 문서로 엽니다.
- **나중에 다시 보기:** 어느 날 어떤 오류를 고쳤고, 무엇을 테스트했으며, 어떤 작업이 남았는지 응답 기록에서 확인할 수 있습니다.
- **다른 AI와 작업하기:** 같은 기록을 참고 자료로 삼아 후속 기획이나 검토를 이어갈 수 있습니다.

답변은 작업 폴더 안에서 날짜와 저장 순서에 따라 쌓입니다.

```text
프로젝트/
└── responses/
    ├── 2026-11-15/
    │   ├── 001_login-error-fix.md
    │   └── 002_test-results.md
    └── 2026-11-16/
        └── 001_remaining-work.md
```

**현재 버전은 v0.1.0 공개 시험판입니다.** macOS의 Codex CLI를 우선 검증했습니다. Codex GUI는 기본 연결을 확인했으며, Work는 실험 지원입니다. Python 3.9 이상이 필요합니다.

기록이 남는다고 AI가 과거 내용을 자동으로 기억하는 것은 아닙니다. [컨텍스트와 기억에 대한 범위](#컨텍스트-문제를-해결하나요)를 참고하세요.

## 시작하기

이 저장소를 내려받거나 배포 ZIP을 풀고, 그 폴더에서 실행합니다.

```sh
python3 response_archive.py install --root "/path/to/project" --timezone Asia/Seoul
```

`/path/to/project`는 **기록을 남길 실제 작업 폴더**로 바꿉니다. 설치 도구는 그 폴더에 스킬·설정과 짧은 프로젝트 안내를 추가합니다. 기존 안내는 보존합니다. 다른 작업 폴더나 사용자 전역 설정은 변경하지 않습니다.

설치한 작업 폴더로 새 Codex 세션이나 로컬 앱 채팅을 시작하고 평소처럼 질문하세요.

- **Codex CLI:** 최종 답변에 `responses/.../001_설명.md` 경로만 표시합니다.
- **Codex GUI·로컬 Work:** 파일 링크를 표시합니다. 클릭하면 앱의 문서 열기와 미리보기 기능을 사용할 수 있습니다.
- **저장 실패:** 답변 전체와 저장하지 못한 이유를 대화에 표시합니다.

처음 설치한 채팅에서 바로 쓰려면 에이전트에게 `$response-archive`를 사용하도록 요청할 수도 있습니다. 이후 새 세션에서는 폴더의 지침을 읽습니다.

## 켜기와 끄기

설치한 폴더의 대화에서 다음처럼 요청합니다.

> 이 작업 폴더의 응답 기록을 꺼줘.

> 이 작업 폴더의 응답 기록을 켜줘.

끄면 일반 답변으로 돌아가고, 다음 세션에도 꺼진 상태가 유지됩니다. 이미 저장한 기록은 남습니다. 켜기·끄기 같은 설정 안내 자체는 기록하지 않습니다.

직접 관리하려면 **설치한 작업 폴더에서** 실행합니다.

```sh
python3 .agents/skills/response-archive/scripts/archive.py status
python3 .agents/skills/response-archive/scripts/archive.py disable
python3 .agents/skills/response-archive/scripts/archive.py enable
python3 .agents/skills/response-archive/scripts/archive.py doctor
```

다른 위치에서 실행할 때는 `--root "/path/to/project"`를 붙입니다. 부모 폴더의 설정을 찾아 다른 폴더에 적용하지 않습니다.

## Git 포함 여부

기본값은 기록 제외입니다. 해당 폴더의 `.gitignore`에 제품이 관리하는 구역을 추가합니다. Git 저장소가 아닌 폴더도 사용할 수 있습니다.

```sh
python3 .agents/skills/response-archive/scripts/archive.py git include
python3 .agents/skills/response-archive/scripts/archive.py git exclude
```

제품이 추가한 규칙만 바꿉니다. 기존 규칙이 계속 기록을 제외하고 있거나 이미 파일을 Git에서 추적하고 있다면 그 상태를 강제로 변경하지 않습니다. 자동 커밋이나 업로드는 하지 않습니다. 내부 설정과 재시도 관리 정보는 항상 제외합니다.

## 제거하기

설치한 작업 폴더에서 실행합니다.

```sh
python3 .agents/skills/response-archive/scripts/archive.py uninstall
```

제품이 추가한 스킬·설정·프로젝트 안내를 제거합니다. 기존 지침에 나중에 추가한 내용도 보존합니다. 설치 파일이나 관리 구역을 직접 수정했다면 자동 삭제를 중단하고 이유를 알려줍니다.

응답 파일은 삭제하지 않습니다. **제거해도 선택한 Git 포함·제외 규칙은 유지**합니다. 기록 제외를 선택했다면 제거 후에도 기록이 갑자기 Git에 노출되지 않습니다. 기록을 포함하려면 제거 전에 `git include`를 선택하세요. 재설치할 때도 이 선택을 이어받으며 `install --git include` 또는 `exclude`로 명시적으로 바꿀 수 있습니다.

재시도 관리 정보, 보존한 Git 선택과 잠금 파일도 `.response-archive/`에 남으며 Git에서 제외합니다. 이 내부 정보를 임의로 삭제하면 이전 답변의 재시도 확인이나 중단된 설정 변경 복구가 불가능해질 수 있습니다.

작업 폴더 전체를 다른 위치로 옮겼다면, 새 위치에서 위 제거 명령을 실행한 뒤 다시 설치합니다. 옮겨진 설정으로 다른 위치에 잘못 저장하지 않도록 저장은 먼저 중단하며, 제거·재설치 과정에서도 응답 파일은 남습니다.

## 저장 규칙

- 답변 원문을 줄이거나 다시 쓰지 않고 UTF-8 그대로 저장합니다.
- 날짜는 설치 시 선택한 시간대의 저장 날짜입니다. `--timezone`을 생략하면 실행 컴퓨터의 현지 시간을 사용합니다. 원격 컴퓨터라면 사용자 시간대를 명시하세요.
- 동시에 저장해도 파일 제목과 관계없이 번호가 겹치지 않습니다. 저장 차례를 기다린 뒤 번호를 확인하고 저장합니다.
- 완성된 파일만 최종 이름으로 나타납니다. 기존 파일은 덮어쓰지 않습니다.
- 동일한 답변을 재시도할 때 같은 식별자를 사용하면 기존 파일을 다시 안내합니다. 같은 식별자로 다른 내용을 보내면 오류로 처리합니다.
- 중단된 저장의 번호는 재사용하지 않을 수 있어 번호 사이가 비어 있을 수 있습니다. 정상 저장은 완료 순서대로 증가합니다.
- 설치·제거·Git 옵션 변경이 도중에 중단되면 다음 명령에서 복구합니다. 중단 후 사용자가 같은 파일을 따로 수정했다면 덮어쓰지 않고 복구 충돌을 안내합니다.
- 한 답변은 최대 32 MiB입니다. 저장 중 대기 시간은 기본 10초입니다.

## 실행 환경 구분

CLI·GUI 구분은 **폴더 설정에 고정하지 않습니다.** 각 호출에서 터미널 환경과 알려진 앱 정보를 확인합니다. 중첩된 터미널처럼 정보가 애매하면 해당 호출에 `--surface cli` 또는 `--surface gui`를 지정할 수 있습니다. 세션 전체에 지정하려면 `RESPONSE_ARCHIVE_SURFACE` 환경 변수를 사용할 수 있습니다. 자동 판단할 근거가 없으면 추측해 저장하지 않고 이유를 반환합니다.

도구를 직접 사용할 때의 예입니다. 이 도구의 JSON 결과를 스킬이 읽어 최종 표시 방식을 결정합니다.

```sh
python3 .agents/skills/response-archive/scripts/archive.py save \
  --surface cli --slug example --request-id unique-answer-001 <<'ANSWER_END_001'
# 답변 제목

원문 그대로 보관할 답변입니다.
ANSWER_END_001
```

같은 답변의 재시도에는 같은 `--request-id`를 사용합니다. 새 답변에는 새 식별자를 사용합니다.

## 현재 확인된 범위

이 도구는 에이전트가 지침을 따르고 저장 도구를 호출하는 방식입니다. 앱의 모든 출력을 강제로 수집하는 기능은 아닙니다. 많은 스킬 때문에 목록이 생략되거나 다른 지침과 충돌하면 기록이 누락될 수 있습니다.

Codex의 명시적 스킬 비활성화 설정은 매 호출에서 다시 확인합니다. 사용자 설정과 해당 프로젝트의 `skills.config`를 읽으며 수정하지 않습니다. 별도 프로필·명령줄 재정의·클라우드 정책 전체를 재구성하지는 않습니다. 호스트가 스킬을 제공하지 않으면 파일을 직접 찾아 실행해 우회하지 않습니다.

실제 시험 결과와 남은 범위는 [검증 기록](docs/VALIDATION.md)에 구분했습니다. Windows, 네트워크 파일시스템, 클라우드 Work는 지원 확인 전입니다. Linux는 POSIX 저장 방식을 사용할 수 있지만 이번 로컬 검증에는 포함하지 않았습니다.

## 컨텍스트 문제를 해결하나요?

**현재 버전은 과거 답변을 보존해 맥락을 다시 확인할 근거를 남깁니다. 모델의 기억이나 컨텍스트 용량을 늘리는 기능은 없습니다.** 컨텍스트는 AI가 지금 답변할 때 실제로 참고하는 정보입니다. 파일이 디스크에 있다는 사실만으로 그 내용이 현재 대화에 포함되지는 않습니다.

| 상황 | 현재 할 수 있는 일과 한계 |
| --- | --- |
| 이전 답변을 다시 확인하고 싶음 | 저장된 원문을 날짜와 순서에 따라 살펴볼 수 있음 |
| 새 세션에서 작업을 이어감 | 관련 기록을 찾아 읽으면 이전 작업 내용을 파악하는 근거가 됨. 자동으로 찾아 읽는 기능은 없음 |
| 대화가 길어져 일부 내용이 압축되거나 누락됨 | 파일에 남은 답변은 다시 확인할 수 있음. 모델의 대화 압축을 제어하거나 누락을 자동 복구하지는 않음 |
| 대화창이 짧아짐 | 화면에 표시하는 본문이 줄어듦. 컨텍스트 사용량이나 토큰 비용의 자동 절감을 뜻하지 않음 |

저장 대상은 **AI의 최종 답변**입니다. 사용자 질문, 도구 실행 로그, 코드 변경 전체를 함께 수집하지 않습니다. 답변에 적히지 않은 요구사항이나 작업 과정은 이 기록만으로 복원할 수 없습니다. 기록의 설명 자체가 틀리거나 오래됐을 수도 있어 현재 파일과 실행 결과를 함께 확인해야 합니다.

현재 구현에는 과거 기록의 자동 검색·선별·대화 삽입 기능이 없습니다. 검증한 것은 원문 보존, 저장 순서, 새 세션과 대화 압축 이후의 기록 동작 등입니다. **과거 작업을 얼마나 정확히 이해하게 되는지에 대한 성능 평가는 아직 하지 않았습니다.**

모델의 대화 압축 방식은 [OpenAI의 Compaction 문서](https://developers.openai.com/api/docs/guides/compaction)를 참고하세요. 이 저장 도구는 해당 압축 기능과 별도로 동작합니다.

## 기술 구성과 Python을 사용한 이유

이 제품은 **Markdown으로 작성한 스킬 지침 + Python 저장 도구 + 작업 폴더별 설정 파일**로 구성됩니다. 답변 생성은 사용 중인 Codex가 담당하고, 이 도구는 파일 저장과 설정 관리를 담당합니다. 별도 서버, 데이터베이스, 저장용 API 키를 요구하지 않습니다. 문서 열기와 미리보기는 기존 앱이나 편집기 기능을 사용합니다.

첫 버전의 실행 코드를 Python으로 통일한 이유는 핵심 작업이 로컬 파일 처리이기 때문입니다. 경로 검사, 날짜 처리, JSON 설정, 내용 해시, 파일 교체와 명령줄 처리를 대부분 표준 라이브러리로 구현할 수 있습니다. Python 3.9·3.10에 없는 TOML 읽기 기능은 작은 라이브러리 `tomli`를 함께 포함해 별도 패키지 설치를 줄였습니다.

언어와 관계없이 동시에 저장할 때 순번이 겹치지 않게 하고, 기존 파일을 덮어쓰지 않도록 구현해야 합니다. 현재 버전은 Python의 `fcntl` 인터페이스를 통한 운영체제 파일 잠금과 파일 공개 절차를 사용합니다. 이런 동작은 다른 언어로도 구현할 수 있으며, Python만이 가능한 기능은 아닙니다.

이 선택에는 제약도 있습니다. 사용자의 컴퓨터에 Python 3.9 이상이 필요하고, 현재 파일 잠금 구현은 macOS·POSIX용이라 Windows에서는 동작하지 않습니다. Python을 사용한다는 이유만으로 모든 운영체제를 지원하는 것은 아닙니다. 첫 버전은 macOS에서 검증했으며 언어별 성능이나 설치 편의성을 비교하는 평가는 하지 않았습니다.

```sh
# 위 평가가 출력한 폴더에서 원문 보존을 별도로 비교.
python3 -B evals/check_transcript.py .tmp/response-archive-native-eval-...

# 공유용 ZIP 생성. 대화·인증·실제 응답 기록은 포함하지 않음.
python3 -B tools/package.py
python3 -B evals/release_eval.py

# Git에 올릴 파일도 추가로 점검. Git 저장소에서 실행.
python3 -B tools/check_release.py --tracked
```

평가용 작업 폴더는 이 프로젝트의 `.tmp/` 아래에 만듭니다. 실제 모델 평가는 임시 설정을 사용하며 사용자 설정을 변경하지 않습니다. 정상 종료와 처리 가능한 실패에서 임시 인증 사본을 제거합니다. 원시 실행 기록은 `evals/runs/` 또는 `.tmp/`에 남겨 로컬에서 확인하며 배포 파일에는 넣지 않습니다.

평가 결과를 보고 문제를 재현하는 사례를 추가하고, 수정한 뒤 같은 사례와 기존 계약을 다시 확인하는 루프로 개발합니다. 제품 요구사항은 [제품 정의](docs/PRODUCT.md)를 참고하세요.

공개 파일은 `release-files.txt`에 하나씩 명시합니다. 폴더에 파일을 추가했다는 이유만으로 배포 ZIP에 포함되지 않습니다. 필수 파일 누락·심볼릭 링크·알려진 비밀키 패턴이 있으면 생성을 중단하고, 기존 배포 ZIP은 보존합니다. Git 검사에서는 **커밋에 들어갈 인덱스의 내용**도 검사하고, 공개 목록 밖 파일과 작업 파일의 차이가 있으면 중단합니다. GitHub 공개 전에는 [적대적 리뷰 결과](docs/ADVERSARIAL_REVIEW.md)를 확인하세요. 패턴 검사는 모든 종류의 비밀 정보를 찾아내는 보장은 아니므로, 공개 대상 파일 목록도 함께 확인해야 합니다. 업로드 후 CI만으로는 이미 노출된 정보를 보호할 수 없으므로 사전 검사를 실행하세요.
