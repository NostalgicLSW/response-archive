# 응답 기록

현재 세션의 작업 폴더에 설치된 응답 기록을 처리한다. 완성된 답변의 내용과 품질을 유지하고 진행 안내·도구 출력·승인 요청은 기록하지 않는다. 사용자의 명시적 요청을 우선한다.

## 매 최종 답변

1. 이 스킬의 `scripts/archive.py`를 사용한다. 스크립트와 설정을 임의로 다시 구현하지 않는다.
2. `python3 -B <archive.py 절대경로> status --root <현재 세션 작업 폴더>`로 최신 상태를 확인한다. 하위 폴더나 부모 폴더의 다른 설정으로 대체하지 않는다. 이미 껐던 사실이나 켰던 사실을 대화 기억만으로 판단하지 않는다.
3. `disabled`이면 일반 답변을 직접 표시한다. 호스트가 스킬을 껐거나 스킬을 제공하지 않는 경우 파일을 직접 찾아 실행해 우회하지 않는다.
4. 켜져 있으면 완성된 답변 **전체**를 UTF-8 그대로 `save --root <작업 폴더> --slug <짧은 제목> --request-id <이번 답변의 고유 식별자> --surface auto`에 전달한다. 답변마다 새 식별자를 정하고, 같은 답변을 재시도할 때는 같은 식별자를 재사용한다. 표준입력 또는 `--input`을 이용한다. 원문을 안전하게 인용하고, 셸이 코드 블록·달러 기호·백틱을 실행하지 않게 한다. 인용된 고유 구분자의 heredoc을 사용할 수 있다. 답변의 마지막 줄바꿈도 저장할 원문의 일부로 취급한다.
5. 실행 환경은 폴더 설정에 저장하지 않는다. 도구가 확인 가능한 환경에서는 `auto`가 구분한다. 현재 실행 화면이 명확한데 자동 판단이 실패하거나 맞지 않으면 **해당 호출에만** `--surface cli` 또는 `gui`를 전달한다. CLI는 터미널 대화, GUI는 Work/Codex 앱 대화다. `TERM`이 애매한 중첩 터미널에서는 대화가 표시되는 실제 화면을 기준으로 한다.
6. `saved` 결과의 `display`만 최종 답변에 표시한다. CLI에서는 경로 한 줄, GUI에서는 파일 링크다. 별도의 제목·요약·본문을 붙이지 않는다. 앱이 링크를 열어 미리보기를 제공하며 자동으로 열었다고 주장하지 않는다.
7. `disabled` 결과이면 본문을 일반 방식으로 표시한다. 오류·도구 누락·권한 부족·시간 초과이면 **저장하려던 답변 전체**와 실제 실패 이유를 표시한다. 성공 경로를 꾸며내지 않는다. 저장 실패 때문에 원래 작업 결과를 잃거나 답변을 줄이지 않는다.

## 설정과 설치

- 기록 켜기/끄기: `enable` / `disable --root ...`. 결과를 일반 문장으로 직접 안내하고 이 설정 안내는 저장하지 않는다.
- 상태 확인/점검: `status` / `doctor --root ...`.
- Git 포함·제외: `git include` / `git exclude --root ...`. 자동 커밋·푸시는 하지 않는다.
- 새 폴더 활성화: 제공된 설치 도구로 `install --root ... --timezone <사용자 현지 시간대>`를 실행한다. 예: 한국은 `Asia/Seoul`. 전역 사용자 설정은 수정하지 않는다. 이미 존재하는 지침은 보존한다.
- 제거: `uninstall --root ...`. 기록을 지우지 않는다. 사용자가 수정한 설치 파일과 지침은 자동으로 삭제하지 않는다.

완료 후 일반 질문, 다음 세션, 맥락 압축 후에도 같은 최신 상태 확인 절차를 유지한다. 이 방식은 지침과 도구 호출에 기반하며 앱의 모든 출력을 강제로 가로채는 기능은 아니다.
